# 미리정비 — 차량 중심 UX 기획

버전: 0.4 · 갱신일: 2026년 11월 7일 · 상태: 앱 1.2.7 화면 반영

아래 차량 중심 구조를 권장 주기와 차량 신호 추정을 함께 쓰는 판정에 적용한다. 현재 구현의 세부 동작은 [1단계 안내](../docs/phase1-maintenance.md)를 따르고, v0.3 이후 바뀐 결정은 [기본 요구사항](service-requirements.md)의 "v0.4에서 바뀐 결정" 표에 모았다. 차량 그림은 투싼 실사 한 장을 쓰고, 투싼이 아닌 차는 같은 그림을 회색 윤곽으로만 그려 다른 차종 이름을 붙이지 않는다.

## 1. 경험의 중심

**내 차 그림에서 관리할 부품을 고르고, 필요한 정보만 하나씩 알려주면 그 부품의 변화를 계속 살펴보는 서비스.**

첫 화면 중앙에 내 차를 크게 놓고, 여섯 소모품의 입체 이미지를 원형으로 둘러 배치한다. 부품 이미지와 차량의 해당 지점을 가는 곡선으로 연결하고 상태는 진행 링·색·짧은 문구로 표시한다. 부품을 누르면 같은 이미지가 상세의 큰 자리로 옮겨 가고, 기록이 없는 부품은 그 자리에서 날짜를 넣는다.

‘토스처럼 직관적’이라는 방향은 **쉬운 말, 한 화면의 명확한 행동 하나, 한 화면에 필요한 입력만, 완료 후 바로 결과 확인**으로 구체화한다. 색상·서체·컴포넌트·주야간 테마·터치 반응은 Pleos 디자인 체계를 따른다. 아래 배치와 문구·전환 방식은 서비스 제안이며 Pleos 공식 템플릿을 뜻하지 않는다.

서비스 범위와 데이터 검증 조건은 [기본 요구사항](service-requirements.md)을 따른다. 이 문서는 그 기능을 사용자가 발견하고 등록하고 확인하는 경험을 구체화한다.

## 2. 첫 화면: 차량 주위에 떠 있는 소모품 이미지

**2026-10-26 디자인 수정:** 양쪽에 사각 카드를 세 개씩 놓던 배치를 폐기한다. 중앙 차량을 크게 유지하고 여섯 소모품 이미지를 60도 간격으로 둘러 배치한다. 원형 상태 링과 부품의 해당 위치를 연결하는 가는 곡선으로 구조를 읽게 한다.

- 위쪽: 엔진오일·오일 필터
- 오른쪽 위: 냉방·난방의 공조 부품
- 오른쪽 아래: 실내 공기 필터
- 아래쪽: 타이어
- 왼쪽 아래: 브레이크 디스크·패드
- 왼쪽 위: 와이퍼

작은 선 아이콘 대신 입체적인 부품 이미지를 사용한다. 부품 사진 뒤에는 옅은 원형 면과 상태 링만 두며 사각형 카드 표면은 사용하지 않는다. 각 이미지 아래에는 부품 이름과 할 일·거리 한 줄만 둔다. 설명문과 판단 근거는 선택 후 상세에서 확인한다.

| 실제 상태 | 그래픽 | 이미지 아래 문구 |
| --- | --- | --- |
| 기록 없음 | 회색 점선 링 | 이력 대기 |
| 기록 작성 중 | 점선 링 | 이어서 기록 |
| 주기 여유 | 회색 링, 쓴 양만큼 채움 | 할 일과 남은 거리·기간("교체까지 183일") |
| 곧 할 때: 30일 또는 1,000 km 이내, 또는 추정이 기준의 90% | 주황 링 | 같은 형식("교체까지 478 km") |
| 점검·타이어 위치 교환 시점 지남 | 주황 링, 문구도 주황 | "지금 점검", "지금 위치 교환" |
| 교체 시점 지남, 차가 잰 값이 기준선에 닿음 | 붉은 링, 문구도 붉은색 | "교체 120 km 지남", 패드 잔량처럼 잰 값 그대로 |
| 와이퍼 작동 소리가 커짐 | 주황 링 | 먼저 닦아 보기 |
| 알림 일시정지 | 판정 그대로 | 챙길 개수에서 빼고, 상세에 "알림 쉬는 중" |

링은 **권장 주기 또는 차량 신호 추정에서 쓴 양**이다. 둘 중 더 많이 쓴 쪽을 채우고, 실제 마모율이나 부품 잔여 수명을 뜻하지 않는다. 몇 %를 썼다는 숫자는 부품 수명으로 읽혀 홈과 판단 근거에 쓰지 않고, 추정 범위와 함께 측정값 화면에만 둔다. 판단할 입력이 없으면 링을 채우지 않는다. 글자를 함께 두어 색만으로 상태를 구분하지 않게 한다.

큰 인사말과 차량 정보 배너를 제거한다. 상단에는 "지금 챙길 게 3개 있어요" 같은 한 줄, 차 이름과 현재 주행거리(예시 데이터면 그 표시), 가장 급한 부품 바로가기, 설정만 둔다. 범례는 두지 않고 링 아래 글자로 상태를 읽게 하며, 화면의 대부분을 그래픽에 쓴다.

좁은 앱 창에서도 사각 카드 목록으로 돌아가지 않고 원형 배치를 유지한다. 차량·원형 이미지 크기와 궤도 폭을 조절하며, 높이가 짧으면 세로로 탐색할 수 있게 한다. 부품 전체를 큰 터치 영역으로 사용하고 이름·상태를 접근성 설명으로 제공한다.

모든 화면은 애플리케이션 윈도 내부에 위치한다. Driving view·상태 표시줄·GNB를 덮지 않고, 주행 규제 시 입력과 상세 탐색을 제한한다. [D1][D2][D7]

## 3. 부품 이미지를 누르면: 이미지가 커지며 상세로

정차 중 부품 이미지를 누르면 다음 순서로 이어진다.

1. 누른 부품 이미지에 Pleos의 눌림 반응을 적용한다.
2. 누른 부품이 상세의 큰 이미지 자리로 옮겨 가고, 나머지 부품은 위쪽에 한 줄로 정리된다.
3. 할 일 한 문장, 이유, 판단 근거, 정비 연결, 기본 버튼이 한 화면에 나타난다. 위쪽 줄에서 다른 부품을 누르면 내용만 바뀐다.

긴 상세 내용을 짧은 확인용 시스템 팝업에 억지로 넣지 않는다. 시스템 팝업은 삭제 확인 등 간단한 의사 결정에 사용한다. [D5]

| 상세 영역 | 기록이 있을 때 |
| --- | --- |
| 맨 위 | 할 일 한 문장("478 km 안에 엔진오일을 갈아 주세요")과 쉬운 말로 된 이유 한 줄 |
| 판단 근거 | 행마다 남은 값, 기준까지 쓴 양의 막대, 막대 양 끝의 지금 값과 기준("실제 6,605 km + 운행 조건 2,917 km" / "권장 10,000 km"). 추정이 상태를 앞당긴 행을 강조한다 |
| 측정값 | 연구 단위·계수·출처와 앱이 본 구간, 못 본 구간. 판단 근거 옆 작은 링크로 연다 |
| 정비 연결 | 부품에 맞는 갈래(방문 교체·정비소·직접 교체) 탭과 예시 업체 카드. 업체를 누르면 방문·예약 시간과 부품·공임별 금액 |
| 기본 행동 | 할 일에 맞는 버튼 하나("교체했어요", "위치 교환했어요", "점검 받았어요")와 "다른 정비 기록" |
| 보조 메뉴 | 더보기의 정비 이력, 알림 일시정지 |

1,500dp 이상 넓은 창에서는 기록이 있는 부품을 한 면으로 그린다. 왼쪽 큰 도면이 상태를 보여 주고 오른쪽에 판단 근거 세 줄을 둔다. 할 일이 없으면 정비소는 "정비소 보기" 링크로 접고 도면을 키운다. 좁은 창은 위 표의 화면을 그대로 쓴다.

| 부품 | 도면 |
| --- | --- |
| 브레이크 패드 | 투싼 투시 도면에서 앞바퀴를 밝히고 렌즈로 패드 단면을 실제 비율로 표시. 패드 교체 기록이 없으면 두께 없이 기준선만 표시 |
| 타이어 | 앞뒤 홈 깊이 렌즈와 차량 도면. 정비소가 함께 열리면 렌즈를 차 옆으로 옮김 |
| 엔진오일 | 권장 거리 링에 실제 거리와 운행 조건 거리를 나눠 표시. 오일량은 앱이 모르므로 병을 채우지 않음 |
| 와이퍼 | 새 블레이드 때와 지금의 소리 크기를 두 원의 실제 비로 표시. 소리 기록이 없으면 기간 링 |
| 냉방·난방 | 기간 링과 냉매 감소 추정 |
| 실내 필터 | 필터 주름 면적 중 먼지 추정 비율만큼 입자를 채움 |

차 투시 도면은 투싼에만 있어 다른 차종은 렌즈만 보여 준다. 내부 구조는 개념도이므로 도면마다 무엇이 실제 비율인지 적는다.

기록이 없는 부품은 맨 위에 "마지막 교체 날짜를 알려 주세요"와 "날짜만 넣어도 다음 시점을 계산해요"를 두고, 기본 행동을 날짜 넣기로 바꾼다.

기본 행동은 현재 상태에 맞는 하나를 강조한다. 관리 설정과 중지·해제는 보조 메뉴에 둔다. 앱을 다시 열면 등록된 항목은 소개 화면을 반복하지 않고 현재 모니터링 정보로 바로 진입한다.

닫으면 같은 부품 이미지로 되돌아오며 원래 화면의 위치와 선택 맥락을 유지한다. 기록 입력은 같은 상세 화면의 내용 전환으로 이어져 모달 위에 모달을 쌓지 않는다. 시스템 뒤로 가기는 수정 중이면 상세로, 처음 등록 중이면 메인으로 돌아간다. 명시적인 닫기는 작성 중 내용을 저장하고 홈으로 돌아간다.

### 움직임의 원칙

- 눌림은 Pleos 가이드의 95% 축소와 모드별 배경 반응을 기준으로 한다. 손가락이 터치 영역 밖으로 벗어나면 실행을 취소한다. [D3]
- 부품 상세 확장은 출발점과 도착점이 이어지는 단일 전환으로 만든다. 질문 전환은 짧고 절제한다. 정확한 시간·이징은 Pleos 모션 값과 기기 검증 후 정한다. [D3][D4]
- 차량 자동 회전, 선을 따라 계속 흐르는 빛, 반복 맥동, 긴 완료 애니메이션은 사용하지 않는다. 상태를 읽는 동안 화면은 안정적으로 유지한다.
- 움직임 축소 설정을 지원하는 환경에서는 짧은 전환으로 대체하고, 애니메이션이 없어도 맥락·초점·상태가 전달되게 한다.

## 4. 첫 설정과 기록: 대략의 답으로 시작하고, 그 뒤는 날짜 하나

v0.3은 소개 화면과 단계별 질문을 빼고 부품마다 한 화면에서 입력받았다. 그러자 처음 연 홈이 여섯 부품 모두 "이력 대기"인 빈 화면이 되었고, 무엇부터 해야 할지 알 수 없었다. v0.4는 첫 실행에만 질문을 하나씩 묻는 첫 설정을 두고, 그 뒤 기록은 상세에서 날짜 하나로 받는다.

첫 설정은 가운데 한 열에 질문 하나를 크게 두고, 위에 전체 순서와 몇 번째인지를 보여 준다. 지나온 단계를 누르면 그 답으로 돌아간다. 모든 단계에 "나중에 할게요"가 있다.

1. **차에서 받을 정보:** 주행 속도, 와이퍼 작동 소리, 차량 위치, 정비 알림을 왜 쓰는지 한 줄씩 적고 "한 번에 허용하기"로 받는다. "이번엔 건너뛰기"도 둔다. 이미 허용된 권한은 이 단계를 빼고 시작한다.
2. **부품마다 질문 하나:** "와이퍼를 마지막으로 언제 바꾸셨나요?"처럼 묻고 "한 달 안", "3개월 전쯤", "1년 넘었어요", "모르겠어요" 같은 보기로 고른다. 엔진오일은 그 뒤 달린 거리를, 브레이크 패드는 점검 뒤 달린 거리만 함께 묻는다. 답한 거리는 차가 알려 준 주행거리에서 빼 기준점으로 쓴다.
3. **타이어:** "지금 타이어는 언제 다셨나요?"와 "이 타이어로 달린 거리"를 년·만 km 단위 보기로 묻는다. 위치 교환, 6년 교체, 홈 깊이 추정이 모두 장착한 때부터 세기 때문이다. 차를 살 때 달려 나온 타이어면 "새 차 때부터"를 고른다. 위치 교환 기록은 나중에 부품 메뉴에서 넣는다.
4. **완료:** "6개 중 2개는 바로 다음 정비 시점을 계산해요"처럼 계산되는 부품 수와 부품별 답을 보여 주고, 줄을 누르면 그 질문으로 돌아간다.

전기차는 엔진오일 질문이 없고, 이미 기록이 있는 부품은 묻지 않는다. "모르겠어요"는 임의 날짜를 만들지 않고 그 부품을 "이력 대기"로 남긴다.

첫 설정 뒤의 기록은 상세에서 받는다. 할 일을 마쳤으면 기본 버튼 한 번으로 오늘 날짜와 차의 주행거리가 기록된다. 예전 정비는 "최근 교체일만 알려주세요" 화면에서 날짜(선택·오늘)를 고르고, 당시 주행거리는 "모르면 비워 두세요"로 선택 입력이다. 주기는 차종 권장값을 "추천 기준"으로 보여 줄 뿐 사용자가 정하지 않는다. 기록은 이력에서 수정·삭제하고, 그 기록이 기준인 주기는 삭제 전에 새 기준이 필요하다고 알린다.

넓은 창에서는 부품 이미지와 내용을 좌우로 나란히 배치하고, 좁은 창에서는 이미지 아래에 내용을 둔다. 모르는 날짜를 임의 날짜로 채우거나, 거리 기준을 쓰지 않는 와이퍼에 주행거리 입력을 요구하지 않는다.

## 5. 등록과 관찰 결과는 별도로 관리

내부 상태는 다음 세 축으로 구분한다. 등록만으로 ‘정상’이 되거나, 데이터가 끊겼는데 이전 정상 표시가 그대로 현재 결과처럼 남는 문제를 방지한다.

| 축 | 상태 | 의미 |
| --- | --- | --- |
| 등록 | 미등록 / 작성 중 / 등록됨 / 일시정지 | 사용자가 해당 항목 관리를 시작했는가 |
| 데이터 | 지원 확인 중 / 초기 수집 중 / 유효 관측 / 부족·오래됨 / 권한 필요 / 일시 오류 / 미지원 | 현재 어떤 관측과 판단을 제공할 수 있는가 |
| 관리 결과 | 판단 전 / 특이 변화 없음 / 변화 관찰 / 점검 권고 / 주기 안내 | 확보된 근거로 어떤 안내를 제공하는가 |

홈에서는 긴 상태를 모두 나열하지 않고 **현재 행동에 가장 중요한 상태 하나**와 짧은 설명을 보여준다. 상세에서는 세 축과 마지막 유효 관측 시점을 확인할 수 있다. 점검 권고와 데이터 중단이 겹치면 `점검 권장 · 새 데이터 없음`처럼 두 사실을 함께 알리고, 이전 결과의 시점을 명시한다. 권한·연결 문제를 부품 이상으로 표현하지 않는다.

등록 완료 후에도 기준이 부족하면 `데이터 모으는 중`, 입력을 얻을 수 없으면 `권한 확인 필요`나 `수집을 잠시 못 하고 있어요`로 표시한다. 수집 진척률은 실제로 정의한 관측 조건과 산출 근거가 있을 때만 사용한다.

v0.4는 부품별 `모니터링 시작` 단계를 두지 않는다. 기록이 생긴 부품부터 추정을 쓰고, 신호 수집은 앱 전체 단위로 설정에서 켜고 끈다. 차량이 어떤 신호를 지원하지 않으면 그 신호가 미지원이라고 적고, 해당 부품은 기간·거리 주기로만 관리한다. 차종에 적용되지 않는 항목(전기차의 엔진오일)은 목록에서 뺀다.

## 6. 끊겼다가 돌아와도 이해되는 흐름

| 상황 | 사용자 경험과 처리 |
| --- | --- |
| 기록 도중 닫기·앱 종료 | 답과 현재 단계를 임시 저장. 부품 아래에 `이어서 기록` 표시 |
| 이전 답변 수정 | 해당 질문으로 이동하고 영향을 받는 후속 답변만 재확인. 다른 답변은 보존 |
| 주행 규제 활성화 | 입력·상세를 가리고 "P단으로 바꾸면 이어서 볼 수 있어요" 표시. 기록 입력 화면의 답은 남기고 그때만 "쓰던 기록은 그대로 남겨 뒀어요"를 붙임. 팝업 안의 입력은 아직 보존하지 않음(2차 PT 전 과제) |
| 창 크기 변경·키보드·시스템 패널 | 선택 항목·답변·초점을 보존. 버튼이 가려지면 접근 가능하게 재배치 |
| 관측 누락·오래된 기록 | 마지막 유효 시점과 현재 판단 한계 표시. 이전 결과를 최신으로 갱신하지 않음 |
| 정비 기록 추가 | 기록 시점 이후 비교 구간을 새로 구분. 입력만으로 정상 판정하지 않음 |
| 알림 일시정지 | 판정은 계속하고 알림과 챙길 개수에서만 뺌. 상세에 `알림 쉬는 중`, 더보기에 `알림 다시 시작` |
| 기록 삭제 | 그 기록이 현재 주기의 기준이면 새 기준을 넣을 때까지 계산할 수 없다고 먼저 알림 |

임시 저장 정보도 차량 내 관리 데이터로 취급한다. 임시 입력 삭제와 차량 데이터 전체 초기화를 지원하고, 차량·사용자 변경 시 다른 차량의 답변이나 관찰 결과를 재사용하지 않는다.

## 7. Pleos 디자인 적용 기준

| 기준 | 적용 방향 | 근거 |
| --- | --- | --- |
| 한눈에 읽기 | 부품 그림 + 이름 + 상태 + 한 줄 설명. 숫자·차트는 상세에 | D1 |
| 차량 화면 구조 | 앱 창 안에서만 표현, 가로·세로·분할 대응, 시스템 영역 보존 | D2 |
| 일관된 조작 | 카드·버튼에 Pleos 눌림 반응, 충분한 터치 영역과 간격 | D1·D3 |
| 연결되는 움직임 | 카드에서 상세로 단일 확장, 질문은 짧은 전환, 반복 장식 배제 | D3·D4·D7 |
| 낮·밤 테마 | Pleos Background·Surface·Text·Informative 등 토큰에 대응. 어두운 차량 그림도 식별 가능하게 | D6 |
| 상태 전달 | 색 + 글자 + 아이콘. 미등록은 중립 상태이며 위험색으로 재촉하지 않음 | D1·D6 및 서비스 제안 |
| 짧은 확인 | 삭제·해제 확인은 적합한 시스템 팝업 사용. 긴 상세와 입력은 앱 내부 화면 | D5 |
| 주행 제한 | CarUxRestrictions와 앱 카테고리·지역 정책에 맞춰 제한 | D7 |

실제 색상값·글자 크기·라운드·간격·터치 영역 치수는 보관한 공식 Figma 및 가이드와 대조해 화면 설계에서 확정한다. 이 문서에서 임의 값을 공식 Pleos 사양으로 정하지 않는다. 폰트 확대·스크린리더 사용 시 이름과 상태를 함께 읽고, 장식 연결선은 탐색 대상에서 제외한다. 상태 변경으로 초점을 강제로 이동하지 않는다.

## 8. 첫 시연에 담을 경험과 완료 조건

첫 시연은 설정의 "예시 데이터로 둘러보기"로 여섯 부품을 한 번에 보여 준다. 예시 데이터는 어느 날 불러와도 지금 할 때 1(브레이크 패드, 제동 에너지), 곧 할 때 2(엔진오일 운행 조건, 와이퍼 작동 소리), 여유 3이 되도록 만들었다. 홈의 차 이름 옆과 업체 카드에 예시임을 적는다. 실제 첫 실행 흐름은 예시 데이터 없이 첫 설정부터 보여 준다.

| ID | 확인 시나리오 | 통과 기준 |
| --- | --- | --- |
| UX-01 | 처음 홈에 진입 | 적용 항목의 위치·그림·이름·상태를 파악하고 하나를 선택할 수 있음. 전체 등록 강요 없음 |
| UX-02 | 카드를 누르고 닫기 | 같은 부품이 확대되어 상세로 이어지고 닫으면 같은 카드로 복귀. 겹친 모달 없음 |
| UX-03 | 이력을 모르는 사용자의 첫 설정 | 한 화면에 질문 하나, `모르겠어요`로 진행 가능, 넘긴 부품이 `이력 대기`로 남는 이유를 이해함 |
| UX-04 | 알려진 이력이 있는 항목 등록 | 기존 정보를 반복 입력하지 않고 확인·수정할 수 있음 |
| UX-05 | 첫 설정을 중간에 건너뜀 | `나중에 할게요`로 빠져도 홈이 열리고, 답한 부품은 바로 계산되며 나머지는 부품에서 이어 넣을 수 있음 |
| UX-06 | 등록 중 주행·앱 종료·창 크기 변경 | 답변·단계 복원, 금지된 입력 재개 없음, 중복 등록 없음 |
| UX-07 | 미지원·권한 거부·데이터 누락 | 정상이나 부품 고장으로 오해되지 않고 가능한 행동을 찾을 수 있음 |
| UX-08 | 정비 기록 입력과 재방문 | 새 비교 구간과 이력을 확인하고 근거 없이 정상으로 바뀌지 않음 |
| UX-09 | 가로·세로·분할·낮·밤 확인 | 카드 이름·상태·기본 버튼이 읽히고 접근 가능. 시스템 영역·창 조작과 충돌 없음 |
| UX-10 | 등록된 항목 재진입 | 현재 상태·유효 시점·다음 행동이 먼저 보이며 수집/주기/관측 판단을 구분함 |

2차 PT 전에는 주행 중에 보여 줄 화면(주행 중 사용 가능 선언 검토)을 출발 음성 안내와 같은 기준으로 설계한다.
